# 每日制作流程

账号：AI趋势观察。固定表达：**每天看懂一个变化，看懂用途，也看清边界。**

## 1. 选一个能解释清楚的变化

轮换已有方向：新功能的实际用途、一个工作场景、机器人应用、能力边界、旧消息更新。每期只解决一个问题。

当天选题保存原始来源链接、发布时间及核验时间。优先查官方公告、文档、更新日志或原论文。标题中的版本、日期、开放范围、价格和数字要回到原始材料核对。仅演示、仅研究结果或分地区开放，应明确说明。没有依据时换选题。

## 2. 填六段脚本

| 段落 | 要完成的任务 |
| --- | --- |
| 问题 | 用一个真实场景引出本期要回答的问题 |
| 用途 | 说明能帮助完成哪一步，给出具体输入和输出 |
| 依据 | 区分官方说明、个人实测和示意图 |
| 边界 | 说明适用条件、限制和需要人判断的地方 |
| 试用 | 给一个可以执行的小任务，不承诺必然结果 |
| 总结 | 一句话收束，可选与本条有关的评论问题 |

复制 examples/episode-demo.json 改文案。每场标题最多两短行，卡片1–3项。当前生成器是固定六场，合计55–75秒；更长内容先精简，不能直接截断配音。

## 3. 生成声音和字幕

Windows脚本逐句合成中文WAV，再用真实采样数形成字幕。改文字后重新合成，不沿用旧字幕时间。换成本人录音或其他配音时，应提供准确分句时间。

运行 build_video.py 生成视频源文件、时间线、脚本和SRT。构建器会拒绝越界音频、重叠字幕、缺失字段及过长文字。新样片的声音选择不代表已复制历史配音。

## 4. 检查并导出

运行 Hyperframes check。查看各场主画面、转场、末帧，播放完整成片确认声音无截断、字幕对应语句。单独生成3:4封面，视频主体保持9:16。

## 5. 发布与复盘

在平台实际预览中检查封面和字幕是否被界面遮挡，按当时页面要求设置内容标识。成片经用户检查后发布。

每条保存来源、稿件版本、生成时间和最终文件。发布后按相同观察时点记录数据，先积累可比记录，再调整标题、选题或时长；一次只改一个主要变量。
