# 每日视频制作提示词

使用方法：复制下面的提示词，填写“当天输入”，附上项目规范和当天可用素材。当前已取得本人主页的三张封面及若干抽样播放帧，账号为“AI趋势观察”；历史音频、完整剪辑节奏仍未全面分析。

视觉参考包括问题式大标题、青蓝强调色、信息卡片、来源说明、字幕及进度线。六段结构、1080×1920、30fps、55–75 秒和 0.4 秒淡化转场是本项目的新制作参数，不是测得的历史源视频参数。

---

请根据我提供的账号资料、已分析样本与当天素材，为“AI趋势观察”制作一条微信视频号的每日视频内容包。

先读取 `DESIGN.md`、`config/style-profile.json`、`examples/episode-demo.json` 和 `scripts/build_video.py`。设计遵守现有颜色、字体、版式；输出 JSON 以当前构建器实际字段和校验为准。样例是常青方法论制作演示，不能当作当天新闻或产品事实来源。

## 先判断依据是否足够

1. 列出已经取得的输入，以及仍然缺少的关键项。
2. 参考作品必须实际可访问。只见标题、封面或片段时，注明分析范围。
3. **沿用视觉模板**：按已观察到的封面与抽样画面组织视觉，不把抽样范围扩大为完整观看，不推定历史音色、配乐、逐镜节奏或源文件分辨率。
4. **调整模板**：用户新要求优先，记录新设置及理由。新制作选择和样本直接观察应分开，不编造账号受众、个人经历或人设。
5. 关键内容不足时只询问会影响成片的最少问题。可以先整理素材、列待填分镜和明确缺口，不虚构事实填满脚本。

对当天新闻、产品功能、发布日期、数字或人物身份，访问并核验当前原始来源，优先使用官方公告、文档、原始论文或当事方材料；标明哪些只是发布方宣称、哪些是实际验证。记录事件发生日期和制作日期，不把“今天制作”改写成“今天发布”。无法核实的结论保留待核验或删去，不能从截图标题补全故事。

每条来源记录至少包含 `id`、`publisher`、`url`、`published_at`、`checked_at`、`claim`、`scene_ids`、`status`。日期未知时写 `null`，`status` 写明已核验或待核验；原创观点和假设案例明确标注内容性质，不给它们编造新闻来源。

## 输出内容包

按以下顺序交付。所有具体文字均应服务于当天主题，而非机械套用固定话术。

### 1. 本条制作简报

- 主题、唯一核心信息、目标时长与画幅。
- 依据哪些账号规则；哪些设置是本次暂定选择。
- 素材清单、缺失素材及可行的替代安排。

### 2. 标题与封面

- 给出 3 个可比较的标题，标明表达角度；不得承诺不存在的结果。
- 推荐 1 组封面文字与构图，并说明与样本或本次选择的关系。
- 封面文字、作品标题和口播开头围绕同一个内容重点。

### 3. 口播或屏幕脚本

- 按六段组织：**提出问题 → 说明用途 → 展示依据 → 讲清边界 → 给出试用方法 → 总结**。这是新模板结构，不声称所有历史视频都采用六段。
- 每段只承担一个任务，每场约 30–45 个中文旁白字，整条约 220–260 字；根据实际配音长度调整，不能用估算冒充实测。
- 开头尽快交代具体问题；中段说明用途与依据，边界与试用方法都要对应本条主题；结尾自然收束，有必要时再添加互动。
- 注明哪些内容属于事实、用户经历、观点或假设。不得编造亲身经历、用户反馈、引用或统计数字。

### 4. 带时间的分镜与声音表

| 起止时间 | 画面 / 可用素材 | 口播 / 屏幕文字 | 字幕与强调 | 声音与停顿 | 转场 | 依据或暂定说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 待生成 | 待生成 | 待生成 | 待生成 | 待生成 | 待生成 | 待生成 |

时间线应连续，段落合计与目标时长一致。脚本阶段的时长是估计值，实际配音或录音完成后再校准，不将估算写成成片实测。

六场默认各 10 秒，总长 60 秒；构建器要求每场 4–25 秒、整条 55–75 秒。旁白过长时优先精简内容，再调整场景时长。场景交接采用同步淡化，字幕和音频不可越过所属场景结束。

### 5. 制作参数

逐项写明画幅、分辨率、帧率、字幕位置与样式、声音来源、音乐安排和导出格式。使用已校准规则；缺失参数可提出暂定值并标明理由，不声称这些参数来自历史作品或平台强制要求。

如果需要生成头像、插图、配音或视频，列明实际使用的工具和产物；未调用工具或未得到文件时，只能报告提示词或制作稿已完成。

### 6. 发布文案与复盘记录

- 给出可直接使用的发布文案；话题词只选与本条相关的内容。
- 记录制作版本、参考样本、实际文件、时长及发布日期。
- 预留发布后的观察值：数据采集日期、页面原标签、可见数值、评论问题、下次可验证的改进。
- 没有发布或没有读到数据时，将相应字段标为“未发布”或“未取得”。

### 7. 可直接交给构建器的 JSON

返回一个完整、有效的 JSON 对象，保存为当天的 `script.json`；不使用省略号、注释或缺失的场景占位。内容未核实时可以返回完整的待填结构，但必须在 `status`、`source` 和正文中清楚标记，不把它称为可发布成稿。

顶层字段：`schema_version: 1`、`channel`、`episode`、`date`、`title`、`scenes`。另附 `status`、`topic` 和 `source_references` 记录内容状态与事实依据；构建器会使用必要制作字段，核验记录仍保留在输入文件中。

`scenes` 必须恰好包含六个对象，推荐 ID 顺序为 `opening`、`use_case`、`evidence`、`boundary`、`small_trial`、`closing`。每场包含：

| 字段 | 内容与约束 |
| --- | --- |
| `id` | 唯一英文标识符，以字母开头，仅字母、数字、下划线或连字符 |
| `label` | 短场景标签，如“第一问 · 用途” |
| `title` | 1–2 个短字符串组成的数组，每行最多约 9 个全角字符 |
| `card_title` | 解释卡片标题，最多 19 个全角单位 |
| `layout` | `list`、`flow` 或 `compare`；对比布局必须恰好 2 项 |
| `items` | 1–3 个 `{ "label": "短标签", "text": "解释文字" }` 对象；标签最多 7、正文最多 26 个全角单位 |
| `takeaway` | 与本条内容对应的一句结论，最多 19 个全角单位 |
| `narration` | 本场完整旁白，保持自然可说，不将制作说明读入正式成片 |
| `source` | 屏幕上的来源短标，最多 32 个全角单位；完整链接放 `source_references` |
| `duration` | 本场秒数，4–25 秒；六场相加为 55–75 秒 |

全角单位由构建器按字符宽度估计，ASCII 字符约计 0.6；最终还须实际预览。标题过长时改写，不缩小到难以阅读。画面文字不要嵌入 HTML 或手工换行。

配音完成后可添加 `audio`、`audio_start`、`audio_duration`：

- `audio` 是相对于 `--output-dir` 的本地 WAV 路径，如 `audio/scene-01.wav`；不使用绝对路径、网址或 `..`。
- `audio_start` 是场内开始秒数，默认 0.5；`audio_duration` 必须填写实际 WAV 长度，二者相加不能大于本场 `duration`。
- 字幕用可选 `captions` 数组：每项含 `text`、`start`、`end`，时间均相对本场开始，满足 `0 <= start < end <= duration`，且各项不重叠。
- 优先按实际音频对齐字幕。无显式字幕时，构建器仅按文本长度估算，并标明 `estimated_by_text_length`；无音频则为 `silent_preview`。不能将这种预览称作完成配音或精确同步。

验证并构建：`python scripts/build_video.py days/YYYY-MM-DD/script.json --output-dir days/YYYY-MM-DD/video`。构建器输出 HTML、`timeline.json`、`script.md`、`subtitles.srt`；渲染与完整试听检查另行完成。

## 交付前检查

- [ ] 核心信息与输入一致，事实有来源，没有虚构账号资料。
- [ ] 返回的六场 JSON 能通过当前构建器校验；引用能对应具体结论及场景。
- [ ] 开头、画幅、时长、字幕、声音、封面、节奏、结尾均已确定，或明确标注暂定 / 缺失。
- [ ] 口播、字幕、画面与时间线相互对应。
- [ ] 预览中字幕可读、主体未被裁切，声音清楚；没有实际预览时明确注明。
- [ ] 已区分“脚本完成”“素材就绪”“视频已渲染”“成片已检查”“已发布”。
- [ ] 上传仓库时仅包含选定模板与代码，不夹带聊天记录、账号缓存、凭据或未经选择的个人素材。

最终回复先说明本次完成到哪个阶段，随后给出可使用的内容或文件，以及影响下一阶段的具体缺口。
